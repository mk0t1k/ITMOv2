# Проблема и метрики

## Проблема

- Пользователь: команда, использующая AI-помощника для ревью PR
- Ситуация: сервис принимает diff и отправляет его во внешний LLM, затем возвращает результат через API
- Что происходит сейчас: в код добавлены ReviewService.review и POST /api/reviews без учёта правил удаления секретов, ограничения размера diff, таймаута и формата ответа
- Почему это мешает пользователю или бизнесу: риск утечки секретов (SEC-1), нестабильность при больших diff (API-1), отсутствие управления таймаутом (REL-1), несоответствие выходного формата требованиям (OUT-1) — снижает доверие и надёжность сервиса
- Что не входит в задачу: реализация реального LLM и UI; любые автоматические действия в GitHub (SCOPE-1)

## Метрики

Выберите измеримые показатели, относящиеся к проблеме. Не используйте VTG, IRR, WACC, CSAT или другую метрику только ради названия.

| Метрика | Текущее значение или способ замера | Целевое изменение | Когда измеряем | Источник данных |
|---|---:|---:|---|---|
| Доля ответов в формате OUT-1 | 0%: код возвращает только `{"comment": ...}` | ≥ 95% запросов | На каждом релизе | Логи и e2e-тесты |
| Доля контролируемых ответов при таймауте LLM (REL-1) | Таймаут LLM приводит к необработанной ошибке (500) | 100%: ошибка превращается в контролируемый ответ | На каждом релизе | Интеграционные тесты с искусственным таймаутом |
| Доля отказов по размеру diff (API-1) | Нет проверки длины diff; oversized diff обрабатывается | 100% запросов с diff > 20 000 символов получают HTTP 413 | На каждом релизе | Интеграционные тесты |
| Число утечек секретов в prompt (SEC-1) | Сырой diff уходит во внешний LLM без редактирования | 0 инцидентов | Еженедельно | Тесты с фейковыми секретами и аудит логов |

## Почему изменение метрики подтвердит решение проблемы

- Рост доли ответов в формате OUT-1 покажет, что контракт ответа выполняется и потребители могут полагаться на структуру `summary`, `risks`, `checks`.
- 100% контролируемых ответов при таймауте (REL-1) снизит неожиданные 500 и повысит предсказуемость сервиса.
- Отказы oversized diff с HTTP 413 (API-1) подтвердят, что сервис защищён от перегрузки и соблюдает лимит.
- Нулевое число утечек секретов (SEC-1) покажет, что diff безопасно отправляется во внешний LLM.
