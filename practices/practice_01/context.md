## Context Pack для первого рабочего сценария

### Факты и правила

- SEC-1: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи. (CASE.md)
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413. (CASE.md)
- REL-1: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ. (CASE.md)
- OUT-1: ответ содержит summary, массив risks (≤3, с file, line, evidence, risk) и массив checks. (CASE.md)
- SCOPE-1: сервис только советует; он не пишет код и не выполняет действия в GitHub. (CASE.md)
- QA-1: риск включается, только если подтверждён строкой diff или правилом. (CASE.md)
- OBS-1: в лог пишутся только request_id, длительность и статус; содержимое diff и ответа не логируется. (CASE.md)

### Формат входа и результата

- Вход: строка diff PR. 
- Выход: объект с полями summary, risks, checks. (CASE.md)

### Ограничения и запрещённые действия

- Нельзя approve, merge или менять код (SCOPE-1). Секреты должны быть удалены до отправки во внешний LLM (SEC-1). Запросы к LLM ограничены по времени (REL-1). (CASE.md)

### Хороший пример

app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов, что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться, что в prompt осталось [REDACTED]. (CASE.md)

### Плохой пример

Код можно улучшить. Добавьте тесты и обработку ошибок. (CASE.md)
### Что пока неизвестно

- Реальные реализации LLM и слой редактирования секретов; поведение при таймауте в текущем коде и при лимите длины diff (не показано в diff)
