Сейчас достаточно интеграционных и e2e-проверок. Из нагрузочных оставлены только сценарии, вытекающие из CASE.md и отличающиеся от одиночных: конкурентный отказ 413 при diff > 20000 (API-1) и конкурентный timeout LLM 10с с контролируемым ответом (REL-1). Показатели RPS/p95/error rate не фиксируем, так как их нет в CASE.md. Условие запуска расширенного профиля нагрузки: появление интеграции с внешним LLM и формально заданных требований по производительности.

## Как использовали AI

- Помог определить противоречия с CASE.md и удалить неподтверждённые метрики (RPS/p95, error rate).
- Не дублировали одиночные сценарии из integration/e2e; оставили только конкурентные проверки по API-1 и REL-1.
- Проверили соответствие условию запуска: нагрузка откладывается до появления внешнего LLM и требований по производительности.
